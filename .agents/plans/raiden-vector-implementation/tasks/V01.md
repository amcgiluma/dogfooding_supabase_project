# Detailed plan: V01 — Verify Vector design, flows, persistence and motion

- Type: verification
- Goal and observable result: Independently demonstrate that the real React app implements the approved Vector composition at desktop/tablet/mobile, retains prototype flows and saved data, and visibly animates finite interactions while respecting live reduced motion and tab visibility.
- Dependencies and inputs: T01 complete and `reports/T01.md` available; `../overview.md`, `tasks/T01.md`, `docs/raiden-interface/vector.html`, `templates/plans/report.md` and `.agents/skills/playwright/SKILL.md`.
- Scope: read-only product verification, isolated browser data, existing checks and screenshots/logs under `output/playwright/raiden-vector/`; write `reports/V01.md`. No product edits, no new tests/framework/dependencies, no live browser/user data, remote changes, deployments or mock mutations. The primary decides correction tasks if failures appear.

## Verification

- Main and edge cases: onboarding validation/back/focus/custom default; chat IME/Enter/multiline/scope; create/type/date/examples; companion rename/switch; permission approve/decline/pause; progress/stages/history/edit; review/corrections/completion/deliverable; recovery/reset/persistence; keyboard/mobile/overflow; live motion preferences and hidden tabs.
- Commands or inspections: npm scripts and diff check; fresh Playwright snapshots and interactions; computed `getComputedStyle`, font checks, geometry and `document.getAnimations()`; context media emulation for live preference; real hidden visibility assertion; storage key/schema/ID assertions within isolated browser data. Screenshots and concise logs support reported claims.
- Expected result: 20 existing tests and typecheck/build pass; real Vector layout at 1440, 768, 390px; every required flow reachable and intact; zero horizontal overflow/browser errors; fonts served locally; motion visible on interactions and entirely finite/static at rest, live reduced-motion honored, hidden work paused/stopped; saved custom names/data unaffected.

## If the plan is insufficient

Tell primary if browser tooling/network restrictions prevent meaningful verification, screenshots reveal a palette-only conversion, any flow loses focus/data, real hidden behavior cannot be exercised, or a check fails. Do not repair product or invent pass evidence. Primary may open a correction task and request targeted re-verification; avoid repeating already-passing checks without a relevant change.
