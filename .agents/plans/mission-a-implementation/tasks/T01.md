Local kind/objective/date/step state survives cancel/reopen; key resets it when companion changes. Remove recommendedDate and initialize date `''`, kind `app`, step 1. Sync `.showModal()`/`.close()` to `open`; schedule opening with a cancellable animation frame so existing Details dialogs close first in their effects. Open/step changes focus objective textarea, checked type radio, or review heading (`tabIndex=-1`) respectively; no refocus on each keystroke/typed character. 5. Compose A's approximately 960px dialog: left conversational content and right 280px persistent mission brief separated by rule. Header shows actual companion name and Cancel; reserved mount sits beside current prompt. Previous submitted answers remain as concise transcript rows after advancing. Stack brief after main content on mobile; dialog fits viewport, scrolls, and all actions remain reachable.

Step 1 prompt “What should we work toward?”, companion guidance, labelled textarea `maxLength=180`, existing concise examples optional, Continue. Trimmed empty/whitespace stays here with role=alert/aria-invalid and focused field. Step 2 prompt “What kind of mission is this?”, native mission-type radio fieldset, optional labelled target date, “A target, not a schedule.”, Back and Review mission.
