## Execution steps

1. Retain four profile steps and the typed `OnboardingInput` draft (`name`, `goal`, `intendedUse`, `companionName`, `appearance`). Initial companion name remains `Morrow`; retain `appearance: 'skull'` solely for snapshot compatibility. Remove APPEARANCES imports, rendered images, radio appearance chooser and appearance wording. Do not change domain types or actions. Final prompt asks the companion's name.
2. Rebuild JSX as a single full-screen onboarding `<main>` with scene behind readable content, an internal `morrow+` wordmark, blue `hello, human.` intro, step count, current monospace question, compact previous question/answer history, current field, suggestions, Back and Continue/Enter chat controls. Match A3 reference: content max 520px, generous quiet black space, large empty 144px corner-marker mascot mount at desktop right and a smaller mount above/below content on mobile. Reserved space must remain blank with no artwork, generic character or initials. Accessible mount label can state reserved future mascot; decorative corners aria-hidden.
3. Keep labels and errors linked to fields; goal/use may remain textarea for multiline input. Keep goal/use suggestions as useful buttons with gray functional backgrounds or understated borders, not decorative pills. All steps validate trimmed nonempty input, preserve entered values on Back and focus the active field after changing steps. Guard duplicate submissions with pending state/ref, disable controls while final action is pending, retain action errors and do not allow animation to block entry or Continue. Remove old marketing intro and verbose integration hint. Keep concise local-device disclosure near final step.
4. After successful `actions.completeOnboarding(input)`, call `navigate({ kind: 'workspace', companionId: result.value.companionId, missionId: null })`. Never navigate home here. The action return already exposes the correct ID. Keep failure in onboarding with visible alert.
5. Implement stellar scene as deterministic sparse points/connections/arcs in inline SVG or a few SVG layers, matching A3's restrained stellar background. Animate at most 2–3 whole absolutely positioned wrapper layers using `transform: translate3d(...)`/small rotation over long 35–90s durations. SVG circles/paths remain static. No random regeneration per render, JS animation loop, particle dependency, filter, blur, box-shadow animation, opacity twinkle or stroke-dashoffset animation. The canvas background stays #000; scene opacity is fixed and low, pointer events disabled, aria-hidden. Add modest fixed charcoal form surfaces #111/#18181b and blue actions.
6. Implement finite typewriter for only the current question, about 20–35ms per character (finish within about 2s). Do not animate history or all page text. Use an effect with cleanup and one bounded timer; reset on step/prompt changes, clean up on Back/unmount. Do not add blinking caret animation. Avoid repeated screen-reader announcement: visual typed copy aria-hidden plus a screen-reader full prompt linked to the input/heading; aria-live only for complete prompts or errors. The full prompt should establish stable height/wrapping or invisible full text overlay so typing does not jump the form.
7. Subscribe to `matchMedia('(prefers-reduced-motion: reduce)')` and `visibilitychange`, cleaning listeners. Reduced motion yields complete prompt and no stellar animation (including when preference changes). Hidden document pauses CSS animation via `animation-play-state: paused` and stops timer; when visible resumes safely or completes the finite text. Never perform state updates every animation frame. If helpers are warranted keep them small, typed and local. Onboarding motion stops when component unmounts into chat.
8. Replace onboarding CSS with feature-prefixed rules, no dependence on old green tokens. Use `var(--accent, #0A84FF)` etc or direct accepted colors. T02 supplies border/fg/muted/blue/gray tokens globally. Main should fill available full viewport; use min-height:100dvh and allow vertical scrolling for long history/keyboard. Responsive content padding about 16px at 390/320. All controls fit 320px, min-width:0, wrap long text, font-size >=16px on text entry. No overflow clipped by scene. Avoid imposing full-page body overflow in feature CSS because T02 controls app shell.
9. Run `npm run typecheck` after edits. Check changed files contain no companion image URLs and no em dashes. Record exact files, checks, any issues and interfaces in `reports/T01.md` using `templates/plans/report.md`.
