- Type: Implementation, Pending T02. Option A and local implementation are authorized.
- Goal and observable result: A selected companion has a visible mission list, its general conversation and a clear create action. Selecting a mission opens the integrated T05 detail with its own conversation. New missions and messages persist through T02 actions without touching another companion's data.
- Dependencies and inputs: Recorded Option A selection with “dale a la uno” and local implementation authorization; completed T02; overview.md, tasks/T02.md, `docs/companions-prototype/visual-options/option-a.html`, AGENTS.md and `.agents/skills/vercel-react-best-practices/SKILL.md`. T05 detail may still be pending; T06 owns final composition. No further visual approval or external publication is required.
- Scope: Own `src/features/workspace/**`, `src/features/chat/**` and `src/features/create-mission/**`, with local styles. Export named `Workspace` from `Workspace.tsx` and reusable named `Chat` from `Chat.tsx`. Do not modify App/global CSS, provider, storage, transitions, seeds, simulation or T05 files. No backend, real AI, background work, credentials or live connections.

No global element selectors/shared `.field`/`.message` styles. T03/T04 run independently without editing App/global CSS. Use persistent data directly; local state holds only form drafts, submission errors and creation visibility. Read the React skill; do not add a router/state/query library.
2. Export `Workspace({ missionDetail }: { missionDetail?: ReactNode })`. Read view from context and narrow `view.kind === 'workspace'` before using `companionId`/`missionId`. Resolve companion through `getCompanion`; invalid selection renders a concise return-home action. Match Option A: header with companion identity and Create mission, then `minmax(0,1fr) 260px` conversation/content and mission-list columns with 40px gap. At 720px and below stack them, keeping mission navigation visible/reachable. Every mission comes from `getCompanionMissions(snapshot, companionId)`, keyed by ID. Home navigation calls `navigate({kind:'home'})`.
3. Mission selection calls `navigate({kind:'workspace',companionId,missionId})`; selecting general chat uses missionId null. Keep the list and create action visible on desktop and accessible through the selected mobile design. Labels use all five states coherently, including **Paused · Ready for review** for awaiting_review. Do not simulate progress or render permission/review controls here.
4. With missionId null, render one `Chat` with scope `{kind:'general',companionId}`. With a selected mission, render only the passed missionDetail slot. T06 passes `<MissionDetail />`; do not import T05 components directly. During independent development a missing slot can show a concise development placeholder, reported as pending integration. A selected mission must never also show a second general or mission chat.
5. Export `Chat({scope}: {scope: ConversationScope})`. Get messages with `getMessages(snapshot, scope)` and submit using `await actions.sendMessage(scope, text)`. Scope is always supplied explicitly, never inferred from an unscoped mission ID. Render user/companion messages as plain text with stable IDs; no innerHTML. Include a labeled multiline input and explicit Send button. Provide concise scope-specific empty copy and a discreet Demo label without claims of actual AI or background execution. Preserve a draft on error; clear it only on successful submission. Disable duplicate sends while pending. Use normal form submit/keyboard access, retaining newline entry in the textarea.
6. Keep each conversation's unsent draft isolated. Mount Chat using `key` derived from scope kind/companionId/missionId when selection changes; drafts may be discarded on leaving a conversation, but may not carry into another scope. No timers or forced scrolling on every render. Keep the input reachable with long messages; do not steal focus when a deterministic reply appears.
7. Build mission creation inside `src/features/create-mission/CreateMission.tsx`; export `CreateMission({companionId,onClose}: {companionId:string;onClose:()=>void})`. Provide app/research/monitoring/custom examples with editable objective text. Example selection is a draft convenience and does not create a mission. Require a trimmed short objective. Offer an optional editable target date with a clearly optional recommended date; compute the suggestion once when opening the form from the user's local calendar, never a UTC-day assumption. Empty date becomes null. Explain minimally that this demo's date is a target, not an active schedule.
8. Submit `actions.createMission(companionId,{kind,objective,targetDate})`, where kind is `'app'|'research'|'monitoring'|'custom'`. T02 validates and returns `{ok:true,value:{missionId}}` or `{ok:false,error:{code,message}}`. Await success, close the form and navigate to the returned mission in the same companion. Keep draft and actionable error on failure, without creating duplicate missions. Creating a mission never replaces existing ones or injects history from another mission. If T05 integration is pending, report the selected new-mission placeholder honestly.
9. For a newly created companion, show zero missions and an honest empty general chat. Make creation discoverable; do not reseed or copy examples into persistent data. Separate mission chat corrections from explicit T05 goal-edit/review actions: conversational text alone never updates an objective, approves a permission or closes a mission.
10. Match Option A on desktop/mobile with an inline rule-separated mission creation form, not a modal. Create mission reveals it and focuses the objective; cancel closes it and returns focus to the trigger. Include example imagery and editable suggestions below the form as approved, collapsing the three example columns to one at 720px. Use visible focus, labeled controls, associated validation via aria-describedby/aria-invalid, failed-field focus and wrapping long text. No decorative cards/pills, subtitle lines above sections, em dashes or continuous animations. Do not copy static preview navigation/scenario tabs into product UI.
11. Run build/typecheck and report exported paths/props to T06 and T05. Verify within integrated App only if available; otherwise describe deferred runtime evidence precisely. Write `reports/T04.md` from `templates/plans/report.md`, including files, commands/results, isolation/creation evidence and pending composition. All shared-contract changes go through supervision.
