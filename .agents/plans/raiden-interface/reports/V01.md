# V01 browser verification

## Result

The final local mocks pass the key layout and interaction checks. I found an empty-state composer issue during the first pass; T01 moved the composer into the shared state area, and I rechecked the corrected flow on all three variants. A later T01 patch added a stage progress indicator; the final screenshots below were refreshed after that patch.

## States and controls

- All six preview states were exercised across the three variants. Onboarding sample actions reach populated state; Start a mission opens the native modal. Direct invalid-state fallback was verified on Vector (`?state=not-a-state` resolves to populated); Command and Signal invalid-state fallback were not separately exercised.
- The corrected empty state keeps its composer visible. In each variant, an example fills and focuses the input without leaving empty state. Whitespace leaves Send disabled and creates no message. Enter adds one local user message and a local acknowledgement, then the URL/state moves to populated.
- On Command, `<img src=x onerror=alert(1)>` rendered as literal message text, with zero image nodes. On Signal, the same string used as a mission objective remained literal text, with zero image nodes. No dialog or script execution occurred.
- Permission Allow once and Decline produced their respective local-only messages in all three variants and moved focus to the result. Reselecting the state reset the action result.
- Review opens at “Deliver summary · Stage 3 ready” with approval actions still visible and no approval result. Approve summary produces a local confirmation and focuses it in all three variants. Request changes opens the labeled feedback field. Blank feedback is ignored; `Clarify who owns the shared account.` saves as literal text in all three variants. Reselecting review clears feedback state.
- Signal Show details updates `aria-expanded`, reveals the three named stages and activity, and responds to Space. Its Missions list opens and closes at 768px while the chat stays in normal page flow.

## Mission creation and focus

Final 390px dialog screenshots are `output/playwright/raiden-{command,signal,vector}-create-390.png`. All are readable within the viewport width, with no horizontal overflow or clipped footer. At 390px the Vector dialog measured 356×646px and Command measured 356×639px. Objective and date controls were 100px and 44px tall; type-choice labels were at least 64px tall, examples 44px, and submit 48px. The default Research radio is selected. The four App, Research, Monitoring, and Custom choices are present.

Whitespace objective submission was rejected in Vector and Signal with “Enter an objective.” Vector creation with Monitoring and the default +7 day date produced a local mission confirmation for Oct 8, 2026. Signal creation with Custom and no date succeeded and reported “No target date.” The date disclosure states that the value is a target and does not schedule work. Command dialog focus starts in Objective; Command's whitespace objective case was not separately submitted.

Native modal focus starts in Objective. Tab stayed in the Signal dialog and wrapped from the close control back to Objective. Escape restored focus to the state selector in Vector and to Start a mission in Signal; the URL returned to the background state. Closing the Vector dialog opened from New mission restored focus to that button. Command's independent Escape restore was not separately exercised.

## Fonts, motion, console, and network

Computed body and heading families were `Plex, system-ui, sans-serif` and `Rajdhani, sans-serif`; `document.fonts.check()` returned true for Plex and Rajdhani on all three pages. Plex is the CSS alias used for the bundled IBM Plex Sans files. The final Vector requests list contained only the page and five local font assets, all HTTP 200; no remote or backend requests were observed. Source inspection found only local preview behavior and a `visibilitychange` handler. Hidden-tab behavior itself was not verified in this headed browser.

The stage progress fill uses a `transform` transition of 0.35s in normal motion; populated stage 2 exposes 67% and scaleX(.67). Reduced-motion emulation changed the progress transition to 0s and disabled the dialog/wordmark animations on all three pages. Source animations use finite durations for the wordmark, dialogs, messages, and controls; progress animates transform rather than width.

After the inline favicon fix, the index and Vector reported zero console errors and warnings. The first index load, before that fix, had one `/favicon.ico` 404; reloading the corrected index removed it. A separate final console capture was not run for Command and Signal. Signal and Command interaction runs did not surface a runtime failure.
